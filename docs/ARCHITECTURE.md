# wb-svg-panel — состояние проекта

Версия 0.3.0. Документ описывает, как всё устроено и почему именно так.
Код — источник истины; здесь то, что из кода не видно.

---

## Что это

SVG-панели умного дома для контроллеров Wiren Board. Демон на Python
подписан на MQTT, держит состояние в памяти, тянет историю для графиков из
`wb-mqtt-db` и отдаёт комнаты как `image/svg+xml`.

Открывается в браузере, на планшете на стене, на телефоне (страница `.html`
работает как PWA). В планах — рендер в PNG для дисплея ESP32-S3.

Репозиторий: `github.com/suklimovich-creator/wb-svg-panel`, лицензия MIT.

---

## Где что крутится

**Первый дом** — `wirenboard-AOEO2W3U`, WB7 (wb-2606), Debian 11, Python 3.9.
Боевой. Живёт на тегах, обновляется через `sh update.sh`.

**Второй дом** — wb-2410, Debian 12. Контроллер друга, прямого доступа нет,
обновляется по присланной инструкции.

Порт 8080 закрыт на обоих. Доступ через `/panel/` за nginx.

## Рабочий процесс

Код меняется только на ноутбуке (Windows, Git Bash). Контроллеры тянут.

```
ноутбук:      правки → git commit → git push
контроллер:   sh update.sh          (боевой, по тегам)
              git pull + restart    (испытательный, ветка main)
```

`config.yaml` в `.gitignore` — у каждого дома свой. `panel.svg.j2` в
`templates/`. Правки шаблона и конфига подхватываются без рестарта
(`auto_reload`, слежение за mtime); правки Python требуют
`systemctl restart wb-svg-panel`.

Файлы от Клода приходят готовыми, кладутся поверх, коммитятся. Готовая
строка `git commit -m "…"` даётся в конце каждой правки.

## Раскладка репозитория

```
panel.py                 точка входа, 13 строк
wbpanel/
  const.py       пути, размеры сетки, постоянные
  config.py      чтение config.yaml, слежение за mtime
  state.py       состояние MQTT в памяти, MQTT-RPC, экземпляр state
  history.py     история: SQLite напрямую либо через db_logger
  geometry.py    цвета, шкалы, сглаживание кривых, раскладка по сетке
  tiles.py       сборка данных для каждого типа плитки (975 строк)
  status.py      строка состояния комнаты
  assemble.py    сборка панели: разделы, геометрия, команды
  render.py      подстановка CSS-переменных
  web.py         HTTP-маршруты, точка входа main() (1535 строк)

tools/                   диагностика и разведка
docs/DEVICES.md          реестр проверенного оборудования
```

Python считает числа и геометрию, шаблон рисует. Арифметики сложнее
умножения на ширину в `.j2` быть не должно.

### Общие объекты

`state` живёт в `state.py` (единственный экземпляр на процесс).
`config`, `history`, `jinja`, `app` — в `web.py`. `assemble.config`
публикуется из `web.main()` при старте: сборка плиток заглядывает в общие
настройки панели, а параметром их не передать — `build_tile` зовётся из
десятка мест. Это единственный обходной путь, всё остальное — обычные
импорты.

## Типы плиток

`chart` · `forecast` · `thermostat` · `ac` · `light` · `dimmer` ·
`curtain` · `switch` · `value` · `link`

Размеры в половинках: `0.5` мелкая (78 px), `1` обычная (170), `2` двойная.
Панели собираются из других через `sections: [{from: kitchen}]`; комнатная
помечается `hidden: true` и служит источником — плитки и статусы
подтягиваются вместе.

Интерактив: `interactive: true`. Демон публикует **только** в топики каналов
нарисованных плиток — белый список собирается из конфига при каждом запросе.

## Грабли, на которых уже стояли

**CSS-переменные резолвятся на сервере.** Старые WebView (Android 5.1,
Chrome 39) и librsvg молча игнорируют `var()`, и половина картинки не
рисуется. `?flat=0` отключает подстановку.

**Селекторы не проникают внутрь `<use>`.** Содержимое символа лежит в
теневом дереве, правило `.active .icon` до него не достаёт. Значки строки
состояния красятся через `currentColor` и атрибут `color` на группе — это
наследуется всегда и переживает подстановку переменных.

**Внутри `<style>` нельзя писать `<`.** Любая угловая скобка, даже в
комментарии, обрывает разбор XML, и librsvg возвращает ошибку без пояснений.

**В комментариях CSS нельзя писать `--имя:`.** Разбор палитры примет это за
объявление переменной и проглотит следующее. Ловилось так: половина цветов
не подставилась, плашки стали чёрными.

**Идентификаторы в SVG нужны с префиксом** (`p-`, `t<N>-`): панель и
раскрытая плитка живут в одном документе и делят `clipPath`.

**`location ^~ /panel/`** требует модификатора `^~`, иначе regex-локация
homeui перехватывает `.html` и `.svg` с 404.

**У `touchend` пустой `touches`** — координаты берутся из `changedTouches`.

**Python 3.9** на Debian 11: проверять `ast.parse(..., feature_version=(3,9))`.
Это делает CI.

## Sprut.hub

**Топики лежат мимо `/devices/`**, на верхнем уровне:
`Sprut.hub-XXXXXXXX_1/accessories/<аксессуар>/<служба>/<характеристика>`.
Панель считает каналом с более чем одним слэшем готовый топик.

**Команды идут в подтопик `/set`.** Запись в топик состояния бесполезна:
мост его не слушает, брокер перетрёт значение обратно. Поэтому для сырых
топиков `command_topic` обязателен — угадывать адрес команды панель
намеренно не пытается.

**Характеристики самоописываются**: рядом со значением публикуются `type`,
`read`, `write`, `minValue`, `maxValue`, `validValues`. Ориентироваться надо
на `type`, а не на номер — нумерация у разных приборов своя.

**Номер аксессуара меняется** при повторном обнаружении. Плитка при этом
показывает последнее известное значение и выглядит рабочей, пока не
попробуешь управлять.

**Шаблоны привязываются в момент обнаружения** — правка шаблона требует
удалить устройство и обнаружить заново.

## Оборудование

Шторы — MoesHouse GM64T (AOK AM68) через Sprut.hub. Разворачивается на лету,
поэтому второе нажатие можно делать разворотом, блокировка не нужна.
`13/15` TargetPosition (запись), `13/16` CurrentPosition, `13/17`

Термостаты — головки через Sprut.hub, аксессуары 288, 289, 290.

Кондиционеры — три Haier AS25S2SF2FA-W через мост `wb-haier` (отдельный
проект). Запись только через облако. Каналы: `power`, `mode`, `target_temp`,
`current_temp`, `fan_mode`, `swing_*`.

Датчики — WB-MSW v.4 в трёх комнатах (`_149`, `_174`, `_232`).
Реле WB-MR6C, WB-MRWL3; диммеры WB-MDM3; ленты WB-LED.

Нормально замкнутые контакты описываются `invert: true` у плитки `switch` —
инвертируется и показ, и команда.

Полный список — `docs/DEVICES.md`.

## Что говорят данные (7 дней истории)

**Движение.** `Current Motion` — не переключатель, а число. Шум держится на
8–11, `Max Motion` (удержанный пик) на 13–16, движение уходит за сотни,
максимумы около 1000. Порог `60` одинаково работает во всех трёх комнатах.
Использовать надо `Max Motion`: короткий проход виден даже при обновлении
раз в десять секунд.

**CO₂.** Медианы 512–541, p95 около 650. Дом проветривается, значок «душно»
на пороге 1000 покажется редко и по делу.

**Шум.** 30–62 дБ, медиана 35–40. Ничего, кроме «в доме живут», не говорит —
в строку состояния не выводится.

**Освещённость.** Максимум за неделю 62–68 люкс у всех трёх датчиков. Это
уровень сумерек, то есть датчики занижают или чем-то прикрыты. Как индикатор
«темно/светло» использовать нельзя, пока не разобрались.

**История пишется раз в 5,5 минут.** Для графиков достаточно, но время
присутствия по ней не посчитать — только по живому MQTT.

**У кондиционеров в истории только `current_temp`.** Остальные каналы в
`wb-mqtt-db` не пишутся: нужна группа в `/etc/wb-mqtt-db.conf`.

## Строка состояния комнаты

Показывает события, а не измерения. Всё, у чего есть плитка с графиком
(CO₂, температура, влажность), туда не попадает — дублировать незачем.
Когда в комнате спокойно, строка пустая: молчание информативно.

Оранжевый чип означает «обрати внимание» — движение, открытая дверь,
протечка. Работающий прибор внимания не требует: чип нейтральный, режим
показан цветом бейджа (холод синий, тепло красное, обдув зелёный, авто —
буква А без цвета).

Значок присутствия: бегущий человечек (поза с дорожного знака «Осторожно,
дети») пока движение есть, стоящий (поза с пешеходного светофора) —
`fade` минут после, затем гаснет.

Давность хранится в памяти процесса и обновляется при отрисовке. Пока
открыта хоть одна вкладка, время идёт; если не смотрит никто — показывать
некому.

Пример описания:

```yaml
status:
  - channel: "wb-msw-v4_149/Max Motion"
    icon: motion
    above: 60
    fade: 20m
  - channel: "haier_bedroom/mode"
    icon: ac-unit
    when: [cool, heat, dry, fan_only, auto]
    badges: {cool: snow, heat: heat, dry: water, fan_only: fan, auto: auto}
    require: {channel: "haier_bedroom/power", when: "1"}
    value_channel: "haier_bedroom/target_temp"
    value_unit: "°"
```

`require` нужен потому, что канал `mode` продолжает сообщать `cool` и после
выключения прибора.

## Правила оформления

Минимум текста, значки вместо слов. Составные значки «устройство + бейдж
режима» вместо отдельного значка на каждый режим. Никакой анимации.
Статусы не дублируют существующие плитки.

Значки: сетка 24×24, обводка 1.8 (фигуры человечков 2.0–2.1), скруглённые
концы. Поправки центровки зашиты прямо в координаты символов, чтобы макросы
о них не помнили. Чип: высота 36, радиус 10 (та же пропорция, что `RX 24`
при 170), поля 7/7 без числа и 10/6/12 со значением — цифры липнут к краю
сильнее, чем скруглённый значок.

Фигуры срисованы с узнаваемых образцов: пешеходный светофор и знак
«Осторожно, дети». Позы важнее толщины линии.

переменные, прогнать через `rsvg-convert` и посмотреть картинку. Это ловит
и то, что сломается на ESP32.
