# wb-svg-panel — как всё устроено

Версия 0.5.0. Код — источник истины; здесь то, что из кода не видно:
почему сделано именно так и на каких граблях мы уже стояли.

---

## Что это

SVG-панели умного дома для контроллеров Wiren Board. Демон на Python
подписан на MQTT, держит состояние в памяти, тянет историю для графиков из
`wb-mqtt-db` и отдаёт комнаты как `image/svg+xml`.

Открывается в браузере, на планшете на стене, на телефоне — страница
`.html` работает как PWA. В планах рендер в PNG для дисплея ESP32.

Репозиторий: `github.com/suklimovich-creator/wb-svg-panel`, лицензия MIT.

---

## Где что крутится

WB7 (wb-2606), Debian 11, Python 3.9. Живёт на тегах, обновляется через
`sh update.sh`.

Порт 8080 закрыт, доступ через `/panel/` за nginx.

---

## Рабочий процесс

Код меняется только на ноутбуке (Windows, Git Bash), контроллеры тянут.

```
ноутбук:      правки → git commit → git push
контроллер:   sh update.sh          (по тегам, с откатом)
```

`config.yaml` в `.gitignore` — у каждого дома свой. Правки шаблона и
конфига подхватываются без рестарта; правки Python требуют
`systemctl restart wb-svg-panel`.

Файлы в проект Клода выгружаются скриптом с переименованием в `.txt`:
загрузчик не принимает `.py`, `.sh` и `.conf`. Выгрузку стоит прогонять
после каждого релиза — устаревшие копии уже четырежды приводили к потере
правок, в том числе к пропаже плитки `header`.

### Общие объекты

`state` живёт в `state.py` — единственный экземпляр на процесс, иначе
фоновый префетч истории тянул бы за собой веб-слой. `config`, `history`,
`jinja`, `app` — в `web.py`. `assemble.config` публикуется из `web.main()`
при старте: сборка плиток заглядывает в общие настройки панели, а
параметром их не передать — `build_tile` зовётся из десятка мест.

## Контракт плитки

Три слоя, каждый отвечает за своё.

**Роль** — что канал значит для плитки: `current` (что прибор измеряет),
`target` (к чему стремится), `state` (работает или ждёт), `mode`, `stop`,
`switch`, `bright`, `temp`, `progress`, `left`, `right`, `value`.

Из объявленных ролей ядро выводит три вещи, которые раньше держались
руками и потому забывались: подписку на MQTT, белый список записи и
проверку конфига. За неделю до введения ролей мы трижды подряд забыли
дописать топик — «стоп» у шторы, канал `require` у чипа, команды
термостата.

**Источник** — как роль превращается в топик:

- `wb` — соглашение Wiren Board, `устройство/канал`, команда с суффиксом
  `/on`;
- `raw` — произвольный MQTT, топик как есть, адрес команды только явный;
- `spruthub` — служба описывает себя сама, роли раскладываются по типам
  характеристик.

Источник выбирается по виду конфига: есть `service` — Sprut.hub; в каналах
больше одного слэша — сырые топики; иначе Wiren Board. Явно заданное
всегда сильнее разобранного автоматически.

**Плитка** объявляет нужные роли, считает данные для шаблона и описывает
зоны нажатий. Ни брокера, ни топиков, ни состояния целиком она не видит —
только узкую калитку `ctx`.

```python
@tile("thermostat")
class Thermostat(Tile):
    roles = ("current", "target", "state", "mode")
    commands = {"target": "command_topic", "mode": "command_topic_mode"}

    def prepare(self, ctx):
        ...
    def zones(self, ctx, data):
        ...
    def pad(self, ctx, data):
        ...
```

`prepare` считает данные, `zones` описывает нажатия, `pad` — то, чем
пульт отличается от плитки: пределы шкалы, геометрия дуги, цвета поля.
Оба получают уже посчитанные данные — считать одно и то же дважды не
нужно, а лишнее чтение канала ещё и добавляет снимок, отчего плитка
ошибочно числится живой.

`fields` и `commands` позволяют плитке называть поля по-своему: у диммера
выключатель зовётся `channel`, у ленты — `channel_switch`. Ломать чужие
конфиги ради стройности незачем.

## Зоны

Зона — это данные, а не код: «в этой области, в такой роли, записать
такое значение». Топик подставляет ядро, взяв его у привязанной роли.

```python
Zone("toggle", "all", "switch", {"on": "1", "off": "0"})
Zone("down", "left", "target", "20.5")
Zone("pad", "long", pad="curtain")
```

Из зоны выводятся три вещи сразу:

- **что писать** — `commands.py` раскладывает зоны в `data-*` по закрытой
  таблице `ZONE_KEYS`. Незнакомое имя зоны — опечатка, и она слышна в
  журнале, а не превращается в тихо неработающую кнопку;
- **куда можно писать** — белый список `/api/publish` собирается тем же
  разбором ролей, что и сами плитки, и отстать от нарисованных кнопок он
  больше не может;
- **куда нажимать** — `left`, `right`, `top`, `bottom` занимают долю
  плитки, и прозрачные прямоугольники под них считает Python, а рисует
  один общий макрос `zone_rects`. Области `all`, `long`, `center` и `pad`
  прямоугольника не требуют: по ним работает вся плитка либо только пульт.

Роль, которую можно лишь писать, привязывается по одному адресу команды —
у «стоп» нет состояния, и требовать канал было бы не за что.

Запасной ход — `Zone(topic=…)`: у приборов, описанных одним полем
`device`, полтора десятка каналов, и роль у всех одна, «часть этого
прибора». Такие адреса плитка перечисляет сама в `writes()`, рядом с
собой, а не в белом списке веб-слоя.

Те же зоны потом можно отдать дисплею ESP32, у которого свой обработчик
касаний и никакого JavaScript.

## Метаданные устройств

**Wiren Board** публикует в `/meta` канала единый JSON: `type`, `units`,
`min`, `max`, `precision`, `readonly`, `title` с переводами, `enum` с
подписями значений. Панель берёт оттуда шаг, единицы, название и права
записи — канал с `readonly` не получает команды даже намеренно. Поля
`unit` и `step` в конфиге нужны лишь чтобы перебить устройство.

**Sprut.hub** говорит на языке HomeKit: аксессуары, службы,
характеристики. Рядом со значением лежат `type`, `read`, `write`,
`minValue`, `maxValue`, `minStep`. Отсюда короткая запись:

```yaml
- type: thermostat
  service: "Sprut.hub-XXXXXXXX_1/accessories/288/13"
```

Ориентироваться надо на `type`, а не на номер характеристики: нумерация у
разных приборов своя.

**Matter** устроен так же — узел, эндпойнт, кластер, атрибут, — поэтому
когда появится Matter-мост, он станет четвёртым источником, а плитки и
конфиг не изменятся. Ради этого роли названы нейтрально: `target`, а не
`TargetTemperature`.

## Типы плиток

`chart` · `forecast` · `thermostat` · `ac` · `light` · `dimmer` ·
`curtain` · `roller` · `switch` · `value` · `link` · `header`

Размеры в половинках: `0.5` мелкая (78 px), `1` обычная (170), `2`
двойная. Плитку можно закрепить на сетке полями `col` и `row`, тоже в
плитках; остальные заполняют свободное. Недостижимая координата не ломает
панель, а теряет силу — иначе один опечатанный `col` оставил бы пустой
экран.

Панели собираются из других через `sections: [{from: kitchen}]`; комнатная
помечается `hidden: true`. Вместе с плитками подтягивается и её блок
`status`.

Интерактив включается `interactive: true`. Демон публикует только в топики
каналов нарисованных плиток.

## Строка состояния

Показывает события, а не измерения: присутствие, открытую дверь, протечку,
работающий прибор. Всё, у чего есть плитка с графиком, туда не попадает.
Когда в комнате спокойно, строка пустая — молчание информативно.

Оранжевый чип означает «обрати внимание». Работающий прибор внимания не
требует: чип нейтральный, режим показан цветом бейджа — холод синий, тепло
красное, обдув зелёный, авто буквой А.

Присутствие: бегущий человечек (поза с дорожного знака «Осторожно, дети»)
пока движение есть, стоящий (поза с пешеходного светофора) — `fade` минут
после, затем гаснет. Давность хранится в памяти процесса и обновляется при
отрисовке.

Нажатие на чип открывает график канала — но только там, где он осмыслен:
у величин с числовым порогом, а не у состояний вроде «дверь открыта».

## Обновление панели

Страница держит один запрос `/<имя>.svg?since=<версия>` открытым. Сервер
отвечает, как только поменялся канал, который эта панель показывает сразу,
а без изменений — через `http.refresh` секунд. Версию он отдаёт в
заголовке `X-Panel-Version`, страница присылает её в следующем запросе.
Если с присланной версии не менялось ничего своего, запрос тоже ждёт, а не
отвечает сразу: версия общая на контроллер и растёт от любого датчика.

Каналы бывают быстрые и медленные. Медленные — графики и прогноз
(`SLOW_TILES`) и чипы с порогом, вроде движения (`above:`/`below:`):
температура и CO2 меняются в сотых каждые пару секунд, Max Motion шумит
каждую секунду, а на экране от этого почти ничего не меняется. Медленные
каналы ждущий запрос не будят, они обновляются по таймауту, раз в
`refresh` секунд. Быстрые — всё остальное: свет, краны, протечки, списки.

Ответ — панель целиком, но браузер разбирает её через `DOMParser` и
сравнивает детей главной группы строками: заменяются только изменившиеся
узлы, обработчики вешаются только на них. Изменились стили, `defs` или
размеры — раскладка другая, панель заменяется целиком.

Готовая картинка кэшируется на сервере, по одной на (панель, колонки,
свёртка, mtime конфига). Перерисовка — когда выросла версия быстрых
каналов самой панели (`panel_version`) или сменилась отметка времени с
шагом `refresh`: часть картинки зависит от часов, а не от каналов (часы в
шапке, точки «давно не обновлялось», кадр камеры, графики из истории). И
не чаще раза в `http.min_render` секунд (по умолчанию 1): пачка изменений
даёт одну отрисовку, а картинка уходит со своей, старой версией —
страница видит, что отстала, и через секунду спрашивает снова. Несколько
экранов на одной панели получают одну отрисовку.

Ждущих запросов одновременно не больше `http.waiters` (по умолчанию
`threads − 6`, то есть 10 при 16 потоках) — каждый держит поток waitress.
Лишний получает короткий ответ 204 без картинки, и страница спрашивает
снова через две секунды. Спрятанная вкладка запрос не держит.

Замер на WB7 (1.12.3): отрисовка «Весь дом» — 0,13 с процессора. Десять
экранов на ней при общей версии и шести местах для ждущих грузили демон до
50–60 %: каждый датчик будил все экраны и стоил отрисовку. После 1.12.4
на стенде с теми же десятью экранами и четырьмя изменениями датчиков в
секунду: отрисовок за 30 с — 3 вместо 65, процессора — в 7 раз меньше.

Чем занят демон, видно в `/stats` (счётчики `stats.py`: отрисовки,
ответы, история, камера, MQTT, процессор по потокам из
`/proc/self/task`) и строкой раз в две секунды через
`tools/watch-load.py`.

## Сворачивание разделов

Заголовок раздела — кнопка: нажатие прячет плитки, оставляя название и
чипы. `accordion: true` у панели включает режим, где раскрыт ровно один
раздел, `tabs: true|bottom` (1.36) — вкладки: полоса во всю ширину
панели над шапкой или под плитками (`assemble.tab_bar`: пилюли поровну по
центру, значок — `tab_icon`, по `icon:` или по названию; подписи — по
`tab_labels`). Шапка получает значок и название открытой комнаты, её чипы
— к чипам панели. Страница (`dockBar` в wrapper.html) прикалывает копию
полосы к краю окна, а полоса в картинке невидима и держит под неё место.
Вид выбирает `assemble.section_mode`: параметр `mode=` из адреса, иначе
ключи панели. Раздел без заголовка не сворачивается ни в каком виде.

Считает сервер, состояние приходит в адресе (`?closed=kitchen`,
`?open=bedroom`, `?mode=tabs`), страница хранит выбор в браузере — свой
на каждом устройстве. Режим узнаётся из разметки: `data-tab` у вкладок,
`data-accordion` у заголовков гармошки. В браузере сворачивать нельзя по двум причинам: адрес
`/panel/all.svg` должен показывать то же, что видит человек (по нему ходит
киоск и пойдёт рендер PNG), и раскладка оказалась бы описана дважды, на
Python и на JavaScript.

Раздел узнаётся по имени панели-источника, а не по номеру: иначе добавили
раздел в середину — и свёрнутым оказался чужой.

## Грабли, на которых уже стояли

**CSS-переменные резолвятся на сервере.** Старые WebView и librsvg молча
игнорируют `var()`, и половина картинки не рисуется. `?flat=0` отключает.

**Селекторы не проникают внутрь `<use>`.** Содержимое символа лежит в
теневом дереве, правило `.active .icon` до него не достаёт. Значки строки
состояния красятся через `currentColor` и атрибут `color` на группе.

**Внутри `<style>` нельзя писать `<`** — даже в комментарии: обрывает
разбор XML, librsvg возвращает ошибку без пояснений.

**Палитра — данные, а не CSS (с 1.24).** Тема — файл
`wbpanel/builtin_themes/<имя>.yaml`: CSS-переменные плюс свойства (`extends`,
`mode`, `on_style`, `inv_kinds`, `sheen`, `shadow`). Блоки переменных в
`<style>` собирает `palette.css()`, сплошной вид берёт значения из
`palette.css_vars()`, а не разбором текста стилей. Всё, что раньше
узнавало тему по имени (тени панели, отсвет, тёмная карточка, подписи
графиков, поля страницы, светлый пульт), спрашивает `palette.info()`;
странице список тем приходит подстановкой `__THEMES_JS__`.

**Витрина тем — панель без MQTT (с 1.28).** `/themes` показывает
выдуманную панель `_demo` из `showcase.py`: у неё своё состояние
(отдельный `WbState`, засеянный значениями) и своя история для графиков.
`render_panel`, `/tile`, `/chart.svg` берут источник через `_source()`;
`/api/publish` топики `/devices/_demo_*/controls/*/on` в брокер не
отправляет, а пишет в состояние витрины — поэтому пульты на ней живые.
Страница витрины — та же `wrapper.html` с флагами `still` (миниатюра:
без ожидания и шагов истории) и `pad` (сразу открыть пульт).

**Форма темы для геометрии — ContextVar (с 1.34).** Край колёс (`edge`)
меняет сами пути, а их считает Python (`ac_disk.gear_path`,
`slots_path`). Тема известна сборке плитки, поэтому `assemble.build_tile`
ставит форму в `form.py`, а геометрия читает её оттуда — своё значение у
каждого потока. Фаска (`bevel`) и глубина (`depth`) — в шаблонах:
`BEVEL`, `DEPTH` в `_base.j2`. Скругление (`radius`, с 1.35) — там же:
`form.radius()` читает `skeuo._clear_corner`, а `rx` шаблона панели
берётся из `palette.info(theme)`.

**Пульты в форме темы (с 1.35).** Пульты рисует браузер, поэтому форма
доходит до них через меню тем: `palette.menu_entry()` отдаёт `depth`,
`edge`, `bevel` и цвета двух теней, `FORM()` в `wrapper.html` читает их у
текущей темы. `openOv` ставит окну классы `neu`/`flat`/`bev-*` и
переменные `--neu-l`, `--neu-d` — ими CSS красит кнопки; ручки
(`knobSVG`, `gearD`) повторяют `gear_path` и фаски шаблонов на JS.

**Колесо кондиционера и пульт фанкойла (с 1.37).** Геометрию считает
Python (`ac_disk.build_arc`, `tiles_fancoil.build_panel`), шаблоны только
рисуют. Пульт фанкойла собран в рамке 354×170 (плитка 1×1 — 170×170,
`build_square`, с 1.38) и вписывается в плитку одним `scale`; части общие:
`slider_block`, `grille_block`, `lcd_block` (размер цифр — от ширины
рамки) и макросы `fc_*` в devices.j2. Две тонкости SVG: свечение почти плоской дуги — фильтр с
`filterUnits="userSpaceOnUse"` и запасом области, иначе область фильтра
по габариту пути обрезает размытие в плоскую полосу; вращение пропеллера
внутри масштабированной группы — SMIL `animateTransform` с центром в
локальных координатах (CSS-поворот считает начало от корня и «водит»
ось). Новые цвета темы (`well`, `key-*`, `led-off`, `lcd`) у встроенных
тем записаны явно, у своих выводятся в `palette._rules`.

**Пульт кондиционера колесом линиями (с 1.39).** `ac_disk.build_screen_arc`
отдаёт те же поля и data-атрибуты, что прежний `build_screen`, поэтому
пульт в `wrapper.html` (`padDisk`) остался один: крутит `.acs-scale`
вокруг оси (она над экраном, `a_sp = 90°`, `dpd < 0` — теплее вправо),
перерисовывает все `.acs-seg` (ореол и линия). По `data-arc` подпись
уставки не прячется, а выделяется, а кружки (`data-sheet`) открывают
шторки `.acs-ch[data-sheet]` (режим, жалюзи); выбор в шторке —
`pickSet`. Вентилятор шторки не открывает — `cycleFan` переключает
скорость по кругу и сразу перекрашивает кружок.

**Стекло (с 1.40).** `depth: glass` добавляет корню класс `depth-glass`
(`palette.classes`). Подложка плитки прозрачна (`.depth-glass .plate`), налёт
и отсвет — один слой `glass-under` под всеми плитками, блик края — слой
`glass-rims` поверх (panel.svg.j2), как слой теней. Размытие «того, что под
плиткой» в SVG недоступно, но и не нужно: обои — мягкие пятна
(`palette.WALL_SPOTS`), размытая их копия выглядит так же. На странице обои —
неподвижный `#pagewall` с CSS-фоном из `menu_entry()["wall"]`, а копия в
картинке (`.wall`) прячется. Отсвет — градиент в координатах панели
(`data-glare`), `glassScroll()` сдвигает его на прокрутку: один атрибут на
кадр. Патч его не сбрасывает: правка живая, сравнение идёт со строкой
сервера.

**Линза стекла и пульт фанкойла (с 1.42).** Обои — группа `wallg` в defs
(`data-wall`): её видно в картинке (`.wall`, на странице спрятан) и
дважды под каждой плиткой (слой `glass-under`, увеличено в 1.08 раза
вокруг центра плитки, обрезано по плитке). `glassScroll()` ставит
прямоугольникам группы место и размер окна браузера в координатах
картинки. Пульт фанкойла — плитка view=pad (`tiles_fancoil.build_pad`,
рамка 390×700, макрос `fcpad`), JS `padFancoil`: колпачок двигает
`transform`, цифры табло рисует `sevenSegSvg` (тот же расчёт, что
`seven_seg`), нажатия — по `data-z` (back, power, mode, key, slider).

**Плитка «Сегодня», цвет карточки, поле страницы (с 1.43).** `today`
собирает строки дел сама, а события — общей с расписанием
`tiles_calendar.event_rows` (с `fill` — завтра на свободное место). Окно
`padToday` ставит друг над другом то же содержимое, что у отдельных окон:
`listView` и `agendaView` возвращают блок и пару start/stop, а `padList` и
`padAgenda` — их обёртки. `color:` у плитки — класс `tint tint-<имя>` на её
группе: `--tile` переопределяется для вырезов (в браузере), а правило
`.tint-<имя> .plate:not(.on):not(.alarm)` даёт цвет и при плоской
подстановке; в стекле — полупрозрачный слой в `glass-under`. Подписи на
поле (`.h1`, `.h2`, часы) красятся `page-*`, у корня это ссылки на
`ink`; свойство темы `page` решает, тёмные ли поле и окна
(`palette.page_dark` → `dark` в меню страницы).

**Маршруты по модулям (с 1.46).** `web.py` держит `app`, сжатие,
`render_panel` и `main()`; маршруты — в `web_live`, `web_tiles`, `web_api`,
`web_pages`, они импортируются в самом низу web.py. Конфиг, история,
шаблоны и клиент MQTT подменяются (`main()`, проверки), поэтому модули
читают их как `web.config`, `web.history`, `web.jinja`,
`web.mqtt_client`, а не копируют при импорте. Рисунки окон —
`/glyph/<имя>.svg` (templates/glyph.svg.j2): макросы плиток, классы красит
`<style>` панели в том же документе, градиенты — её `<defs>` (uid «p-»).
Стили плиток — макрос `style()` в файле плиток, каркас склеивает их в
единственный `<style>`: base, basic, chart, devices, ac.

**Обновление без головы, сжатие, облегчённо (с 1.45).** Главная группа
панели помечена `data-main="1"`; всё до неё — голова (корень, `<style>`,
`<defs>`). Сервер отдаёт её отпечаток в `X-Panel-Head`; страница помнит
голову (`HEAD` в update.js) и шлёт `have=<отпечаток>`, совпало — ответ без
головы (`X-Panel-Lean: 1`, `web.lean_head`), страница приставляет её сама
(`takeSvg`). Голова сравнивается исходным текстом, а та же самая картинка не
разбирается вовсе (`shownSvg`). Ответы сжимает `web._gzip` (after_request;
поток камеры — нет, файлы static/ — да). `lite=1` в адресе — выбор
устройства «облегчённо»: `shadows` выключены, у стекла нет линзы и отсвета,
страница ставит SMIL на паузу. `?perf=1` — плашка замера (core.js, `perf*`).
Без адреса «облегчённо» включается само на слабом устройстве (`weakDevice()`
в core.js, с 1.47: нет PointerEvent, Android до 8, памяти или ядер до 2).

**Голова не зависит от раскладки (с 1.47).** Всё, что меняется с высотой
панели или набором плиток — фильтры теней, обои стекла (`wallg`), обрезка
плиток — первым `<defs>` внутри главной группы, а не в голове. Высота
корня (`height`, `viewBox`) в отпечаток головы не входит ни на сервере
(`ROOT_SIZE` в web_live.py), ни на странице (`headKey`); с ответом без
головы сервер шлёт `X-Panel-Height`, страница ставит её в свою голову
(`withHeight`), а `patch()` переносит размер на показанную картинку
(`sizeFrom`). Число частей главной группы поменялось (раздел свернули, чип
появился) — `merge()` сводит их по совпадающим строкам, полной замены нет.
`?perf=1` показывает причины полных замен (`patchWhy`) и число сведений.

**Части — из текста (с 1.48).** `applySvg` сначала пробует `patchText`:
`splitMain` режет детей главной группы прямо из текста ответа (поиск `<`
и `>` с учётом вложенности; шаблон экранирует угловые скобки в
атрибутах), `sync` сравнивает куски со `shownParts` и просит
`parseParts` разобрать только новые — одним маленьким документом.
Разбор всей картинки остаётся для первой загрузки, смены головы или
раскладки и для запасного пути: `full` сверяет резку с разбором
браузера, не сошлось — `TEXT_PARTS = false`, дальше `patch` через
`XMLSerializer`, как до 1.48. Пока листают (`lastScroll` в пределах
`SCROLL_QUIET`), ответ ждёт в `pendingSvg`, как и при нажатом пальце.
С 1.49 `parseParts` разбирает куски `createContextualFragment` в
контексте главной группы (HTML-разбор в SVG-контексте даёт те же узлы —
сверено на 510 картинках), без `importNode`; не вышло — `HTML_PARTS =
false` и XML. `bind(node, true)` вешает обработчики только в части,
общий `bindPanel()` — один раз после `sync`.

**Обои своей картинкой (с 1.50).** `wallpaper.py`: путь из `wallpaper:`
(панель или конфиг) → ключ (sha1 пути, времени, размера, `RECIPE`) →
`/wall/<ключ>.jpg` (web_tiles), размытый Pillow JPEG в памяти. `web.wall_of`
даёт шаблону `wall_img` и вуаль `wall_dim` только для `depth: glass`;
`wallg` рисует `<image>` и вуаль вместо пятен, корень несёт
`data-wall-img`/`data-wall-dim` — по ним страница строит фон `#pagewall`
(`wallCss` в core.js), `glassScroll` двигает и `image`.

**Кнопки страницы в ряду вкладок (с 1.50).** При полосе сверху и `nav=`
`tab_bar(nav=True)` оставляет по краям место под два круга
(`tab_plate.nav`), шапка рисуется без кнопок (`nav_w = 0`, `tab_nav`).
`dockBar` прижимает копии кнопок к краям окна (свой `scale(1/scaleX)`
вокруг 0 и W) и вешает `navTap`.

**Ручки (с 1.51).** `CONTROLS` (wrapper.html, из `live_controls` и
`tile_gestures`) и выбор устройства (`LIVE_MODE`, `DRAG_MODE` в
localStorage) → `liveOn()`, `dragOn()` (core.js). `liveSender(send, ms)`:
`tick()` — не чаще `ms` и не при отправке в пути, `end(fn)` — последнее
значение цепочкой после всех. Пульты: `padLevel`, `padSphere`,
`padCurtain`. Жесты — `static/js/gestures.js`: `tdMove`/`tdEnd` зовутся
из обработчиков плиток (press.js); ось по `data-kind` (`TD_AXIS`),
вертикальные — только если страница не листается (`tdMarks` → классы
`tdrag`, `tdrag-v` → `touch-action` в panel.css); `tdModel` — что и как
слать (те же `data-*`, что у пультов); плашка `#tdrag`.
С 1.52 — `static/js/live-tiles.js`: `liveTile(node, m)` → `{set(v)}` по
виду плитки (`LIVE_TILE.dimmer/light/thermostat/ac/fancoil/roller/
curtain`) перестраивает в самой плитке то, что зависит от значения, той
же геометрией, что сервер (skeuo.py, ac_disk.py, sky.py, шаблоны). Фанкойл
— общие с пультом `fcData`/`fcShow` (pads-climate.js) и `data-fcl` у группы
плитки. Перерисовка — `tdPaint` через requestAnimationFrame; по
отпускании `hold(node)` держит нарисованное до ответа прибора.

Скрипты страницы — обычные файлы с общими глобальными именами, без модулей:
код, выполняемый при загрузке, зовёт только функции из своего и предыдущих
файлов (проверяет `tests/js_check.js`).

**Кнопки страницы в шапке (с 1.44).** Страница просит картинку с
`nav=<масштаб>` (1.0–1.6): `prepare` отодвигает название и чипы на
`nav_w`, шаблон рисует `[data-nav="back"]` и `[data-nav="menu"]` (кружки
класса `chip`). Масштаб страница считает по ужатию картинки (`navScale`:
ширина viewBox / ширина на экране) и перезапрашивает, если он сменился.
Есть кнопки в картинке — класс `svgnav` у корня страницы прячет прежние
`#back`/`#cols` (они остаются запасными для панели без заголовка). Меню
шестерёнки — `#navmenu`, `drawMenu`.

**Окно на весь экран — одна шапка (с 1.35).** `padHead` — «назад»,
название, справа «i» или питание. Окна, собранные со старым заголовком
`.ttl`, `openOv` переводит на ту же шапку; у окон без шапки (списки,
краны, календарь) — та же круглая «назад» слева сверху (`#ov .close`).
«i» прячет `.hint` окна, у графика — перезапрашивает картинку с
`?info=1` (пояснение к зонам рисует сервер).

**Редактор тем — черновики в памяти (с 1.29).** Страница шлёт тему в
`/api/theme/draft`; `palette.draft()` прогоняет её тем же путём, что и
файл из `themes/` (`_theme`, производные `_derive`, контраст), и кладёт
под именем `draft-<хэш содержимого>` в `_DRAFTS` — последние 16. В
списки и меню черновики не попадают, но `exists()`/`get()` их знают,
поэтому `?theme=draft-…` работает везде, где тема из адреса. Файл темы
пишет `palette.to_yaml()`; на диск сервер ничего не кладёт — файл
скачивают. Генерация из акцента и разбор фото — в браузере.

**Идентификаторы в SVG нужны с префиксом**: панель и раскрытая плитка
живут в одном документе и делят `clipPath`.

**`location ^~ /panel/`** требует модификатора `^~`, иначе regex-локация
homeui перехватывает `.html` и `.svg` с 404.

**У `touchend` пустой `touches`** — координаты из `changedTouches`.

**Панель обновляется точечно, и под открытым окном тоже.** С 1.11.0 в
документ попадают только изменившиеся дети главной группы, остальные узлы
живут дальше. Но изменившаяся плитка — это новый узел: пульт, который
держит ссылку на плитку, должен переискивать её по `data-i`, как это
делает термостат.

**Ждущий запрос видит только свои каналы.** Версия состояния общая на
контроллер, поэтому `/<имя>.svg?since=` сверяется с `state.touched` по
набору быстрых каналов панели (`panel_watch`). Новый тип плитки, который
читает что-то мимо ролей и `channels()`, будет обновляться только по
таймауту — добавьте его каналы в `channels()`. Новый тип, которому хватит
обновления раз в `refresh` секунд, — в `SLOW_TILES`. Списки и прочее не из MQTT поднимают
версию через `state.bump("метка")`, а плитка добавляет метку в набор.

**Python 3.9** на Debian 11: CI проверяет `ast.parse(feature_version=(3,9))`.

## Что дальше

**Техдолг.** Перевести слой команд на зоны — после этого белый список и
подписка выводятся из реестра, а не собираются вручную. Разрезать шаблон
на `templates/tiles/*.j2`. Отчёт о проверке конфига на странице вместо
журнала.

**Возможности.** `type: auto` — плитка угадывается по набору характеристик
службы. Мгновенный отклик при сворачивании: браузер прячет сразу, сервер
догоняет. Автозагрузка чужих плиток из папки — только после того, как
контракт устоится: демон работает от root.

**Устройства.** Пылесос ждёт правки шаблона Sprut.hub — сейчас мост не
отдаёт прогресс уборки и возврат на базу. Телевизор Samsung требует
отдельного демона с постоянным соединением, как `wb-haier`, иначе дикая
задержка. Камера HiWatch не куплена. Сцены на кнопках Wiren Board — по
сути тот же выключатель. Задачи с галочками единственные требуют памяти;
чище всего хранить их в retained-топиках wb-rules.

**Наблюдения по данным.** Освещённость у всех трёх датчиков WB-MSW
занижает в разы — максимум 68 люкс за неделю, уровень сумерек. Пока не
разобрались, как индикатор «темно/светло» использовать нельзя.
